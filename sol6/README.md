# sol6 — shop-demand-sized farm (NOT submitted)

sol6 keeps sol5's feeder-crew / greedy crop-crew machinery but replaces every
fixed animal and crop count with **targets sized from the shops that have actually
unlocked**. The town draws its shops randomly (but observably), and that draw is
what decides whether milk, wool, eggs or strawberries are worth money in a given
game. sol5 commits to one fixed livestock mix; sol6 reads `obs.town.unlocked_shops`
each turn, converts it to a per-product daily **sink** (units/day the town will
drain), and sizes production to the sink.

The strategy vector is a set of **design values from PLAN.md, not CEM-tuned**
(the brief forbids CEM). `SEED_VEC` lives in `farmlib.py`.

## Files

| File | Purpose |
|---|---|
| `farmlib.py` | The agent. `build_agent(params_or_vec)` returns the `agent(obs)` closure. `PARAM_SPEC` / `SEED_VEC` hold the 24 knobs. |
| `main.py` | Self-contained submission: `farmlib.py` source + `agent = build_agent(VEC)`. Generated by `make_main.py`; verified byte-for-behaviour identical to `build_agent(SEED_VEC)`. |
| `make_main.py` | Bakes a vector into `main.py` and checks it reproduces `build_agent` on seeds 200/201 vs pass. |
| `arena.py` | Forced-shop-schedule harness. `play(spec0, spec1, seed, schedule)` monkeypatches `K._end_of_day` to force each newly-unlocked shop to a scripted type, then records scores, per-product revenue, animal counts/day, fed%, escapes, idle unit-turns, walking share and max latency. `run_matrix(me, opponents, schedules, seeds, workers, both_seats)` runs a grid in a process pool. |
| `results/*.json` | Saved gate runs (see below). |
| `PLAN.md` | The design spec (kept as-is). |

## How to run

Python: `/opt/miniconda3/envs/env2/bin/python` (kaggle_environments 1.32.7).

```bash
# rebuild + verify the submission file
python make_main.py

# full gate grid: 5 named schedules x {sol5,gideon} x both seats x seeds 11,12
python - <<'PY'
import arena, json
r = arena.run_matrix("sol6", ["sol5","gideon"], arena.NAMED_5,
                     seeds=[11,12], workers=10, both_seats=True)
json.dump(r, open("results/grid.json","w"))
PY
```

`arena.NAMED_SCHEDULES` has five hand-built shop scripts that isolate a market:
`milk_starved`, `yarnless_3milk`, `yarn3`, `milk_rich`, `bakery_heavy`
(`arena.NAMED_5` is the list). `arena.random_schedule(k)` draws a legal random one.
Opponent specs accepted by `play`/`run_matrix`: `"pass"`, `"sol6"`/`"self"`,
`"sol5"`, `"gideon"`, or a raw parameter vector.

## What changed from sol5 (the pivot)

1. **Livestock sized to shop sinks.** cows/sheep grow with the milk/wool sink we
   expect to capture; a flooded product's surplus animals are **CULLed** (left to
   escape on purpose, freeing labor). There is no alternate-day feeding mode.
2. **Geese sized to the egg sink, not to idle labor.** This is the single biggest
   fix: sol5-style idle-labor geese put 6 birds on the board in milk-rich draws
   where eggs are worthless, stealing cash and builder-turns from the 10th cow.
3. **Cow anticipation.** Cows need ~8 days after placement to yield, so a milk
   signal that only arrives after the day-19 buy deadline is useless. When a real
   milk sink is already visible early, sol6 leans toward the cow cap.
4. **Crops sized to sinks** (strawberry scaled to its sink up to 32 tiles; melon
   front-loaded day 0-1; wheat rolling; carrot tail-filler; tomato only with a
   tomato shop).
